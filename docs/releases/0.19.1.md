# Skalling 0.19.1 — 2026-11-06

Una auditoría de Actas entró en un workflow de implementación después de clasificarse
correctamente como auditoría. El informe ya existía cuando el motor exigió pasar por
Teo y Sol. Esta versión separa esos recorridos.

## Comportamiento

- Alex delimita alcance y registra `classify --kind audit --record`; Luz analiza y
  entrega conclusiones. No hay `start`, plan, `deliver` ni aprobación de código.
- Jhon contrasta afirmaciones críticas o dudosas concretas cuando hace falta. Las
  correcciones del análisis corresponden a Luz, conservando evidencia y limitaciones.
- Luz distingue hechos, hipótesis y mediciones. Una búsqueda local no demuestra
  ausencia en todo el repositorio; una lectura estática no mide latencia ni coste real.
- El guard y el writer rechazan mutaciones de memoria por otros roles de Skalling,
  incluso si tienen permiso de shell. Pau persiste sólo hallazgos validados. Un documento en el repositorio se crea si
  está pedido; guardar memoria no retrasa la entrega del diagnóstico.
- Si una auditoría antigua sigue activa como código, Alex puede cancelar ese workflow
  con evidencia del error y continuar la auditoría con sus pendientes. Cancelar no
  aprueba hallazgos ni borra historia. No se migra automáticamente ninguna auditoría.

## Contrato del motor

El plugin exige `request_kind: "code"` explícito para `start`; las demás acciones y
workflows anteriores siguen funcionando. El backend rechaza tipos no-code antes de
inicializar almacenamiento. Los clientes Python anteriores que omitían ese campo
mantienen compatibilidad; el canal de OpenCode exige la elección explícita.

No se usa un detector textual ni un bloqueo persistente por sesión. Auditar y luego
implementar una corrección autorizada en la misma sesión sigue siendo posible.
Esta protección no puede demostrar que el modelo clasificó bien si declara `code`
incorrectamente; las instrucciones y pruebas cubren la distinción solicitada.

## Validación e instalación

Pruebas de plugin y motor: clasificación ausente/no-code rechazada sin ejecutar el
backend o crear un workflow; corrección de hallazgos con tipo code permitida; lectura
y cancelación de estados antiguos conservando historia y sin emitir aprobación Git.
Contratos de agentes, tamaño de prompts, permisos y distribución instalada se verifican.

Actualizar global y proyecto mediante `/skalling-update` y abrir una sesión nueva:
el plugin y los prompts ya cargados no se sustituyen por cambiar archivos en disco.
La migración 069 sólo actualiza versión; no cambia modelos, hallazgos ni workflows.

Rollback: reinstalar el bundle anterior revierte instrucciones/guard de clasificación;
conservar los backups y no borrar ni restaurar TeamDB para revertir estos cambios.
