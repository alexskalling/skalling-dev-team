# Skalling 0.18.0 — 2026-11-06

Esta versión reúne las correcciones y mejoras comprobadas al usar el equipo de
agentes en actas3.0.0. Disponible desde el checkout local; esta actualización no
crea un tag ni publica un Release en GitHub.

## Comportamiento

- Jhon y Luz conservan planes propios; ampliar las comprobaciones exige una
  carencia concreta de evidencia. Las pruebas de transformación deben comparar
  salidas completas, incluyendo orden y contenido conservado.
- Las inspecciones nativas leen archivos y su base Git sin shell arbitrario.
  Su reutilización identifica archivos, contenido, base y motor; no recorre
  dependencias ni caduca por tiempo. Compartir evidencia no comparte aprobaciones.
- Sin `testing.fast`, una verificación no elige automáticamente la suite completa.
  `testing.unit` requiere selección explícita y justificación del impacto.
- Un check incorrecto se repara en la entrega vigente. Una nueva instrucción humana
  puede habilitar otra entrega del workflow bloqueado sin borrar su historial.
  `recover` admite registrar la instrucción y continuar en una transacción atómica.
- El runtime informa qué backend y plugin se usan y detecta diferencias entre
  plugin cargado y disco. El prompt completo cargado por el agente no es observable.
- Se separan tiempo de comando y validación de caché. Los tokens obtenidos de
  ventanas de sesiones no se presentan como contabilidad exacta por workflow.
- Se incluyen los ajustes de instalación, comandos/modelos y Git hooks aplicados
  durante el diagnóstico. Global y local se verifican por versión y contenido;
  las asignaciones de modelos se conservan.

## Actualización y datos

`VERSION`, manifiestos de instalación, esquemas y `schema_meta.version` quedan
alineados en 0.18.0. La migración 067 modifica únicamente esa marca de versión;
las migraciones previas siguen atendiendo a las bases más antiguas. No se cambian
los IDs de workflows, hallazgos, aprobaciones, límites ni memoria del proyecto.

Las instalaciones local y global deben sincronizarse. Las sesiones abiertas
pueden conservar el plugin y las instrucciones anteriores hasta recargarse.
No hace falta empezar de nuevo los workflows.

## Validación y límites

Las pruebas de motor, revisión, recuperación, plugin y paquete instalado cubren
los cambios. La coherencia de versiones y la migración de una DB existente se
verifican al preparar esta versión.

En actas, validar las entradas reutilizables de un diff pasó de una mediana de
2297,978 ms a 0,349 ms en tres muestras por método. Esto mide una operación del
motor, no la duración total de una conversación ni un ahorro exacto de tokens.
Detalle: [ejecución con menos espera](../execution-efficiency.md).

No se declara una versión 1.0 estable ni una certificación de CI remota. La
publicación del release es un paso distinto de instalar este checkout.
