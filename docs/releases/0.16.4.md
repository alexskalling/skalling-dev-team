# 0.16.4 — verificar sin reinstalar dependencias

El registro de betterhealth muestra que `pnpm run test` invocó `pnpm install`
antes de ejecutar las pruebas y cambió `@astrojs/react`. El helper de aprobación
ejecutaba el comando configurado, pero pnpm habilitaba la instalación implícita.
Además, la configuración del proyecto conservaba pnpm pese a tener lockfile npm.

El motor de checks y `skalling-verify.sh` fijan `verifyDepsBeforeRun=false` con
las variables de configuración de pnpm actuales y legacy. Se verifica con las
dependencias ya preparadas; si falta alguna, el test puede fallar y conserva su
código de salida. Esto no bloquea instalaciones escritas explícitamente dentro
de un script del proyecto, ni modifica las órdenes de una terminal independiente.
Referencia: [configuración oficial de pnpm](https://github.com/pnpm/pnpm.io/blob/main/versioned_docs/version-10.x/settings.md#verifydepsbeforerun).

La regresión RED detecta el efecto en ambos verificadores. La prueba opt-in
`python3 tests/runtime/pnpm-verifier-smoke.py` usa pnpm real con configuración
`install`, sin node_modules y con una dependencia inexistente: el test corre,
no aparece lockfile ni node_modules y los manifiestos permanecen idénticos.
Resultados: motor 79/79, gate de verificación 9/9, paridad de scripts 11/11,
espejos 14/14 y coherencia de versión 11/11. Prueba real con pnpm 11.5.1.
Instalados y comprobados fuente, global, betterhealth y gestor3.0 en 0.16.4;
modelos, configuración del consumidor e índice preservados.

En betterhealth se corrigió únicamente el comando de tests a `npm run test`,
con respaldo de project.yaml: 39 tests pasan. Ese resultado corresponde al
HEAD actual, no certifica los 44 tests de una entrega histórica ni los cinco
outcomes de SEO. No se publicó el producto ni se alteró su rama o índice.

Rollback: revertir las variables de los dos verificadores y sus regresiones;
no requiere cambiar dependencias del consumidor. Migración 062: solo versión.
